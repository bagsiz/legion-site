A terminal for Claude Code

One repo. Many Claudes. One screen.

Legion runs several Claude Code sessions side by side in one terminal. Each session works in its own git worktree and branch, so they never trample each other, and you can see at a glance who is working, who needs you and who is done.

Each pane runs Claude Code's own interface. The pane titles and the status bar come from Claude Code hooks.

Commander

Write one goal. Planning, hand-off and follow-up are on it.

The commander is a Claude that splits the work into tasks and runs the worker sessions for you. You give the goal and merge what is ready.

By hand

You split the job in your head.

You write a brief for every task.

You open sessions and assign them one by one.

You watch the panes to see who finished.

You read every diff yourself.

You close the finished panes.

With the commander

It reads the code and splits the goal into tasks that don't collide on files.

It writes acceptance criteria for each task.

It starts the workers and assigns the tasks.

Every finished job is reported to it automatically.

It checks the diffs, asks for fixes and tells you the merge order.

When you merge, it closes that worker's pane.

Why

Running agents in parallel is easy. Keeping them out of each other's way is not.

Opening a few Claude sessions takes seconds. The work is in making sure they don't overwrite each other and that you notice when one is waiting for you.

Two sessions in one folder overwrite each other's files.

Every session works under .legion/worktrees/<name> on its own legion/<name> branch.

You click through tabs to find the one asking for approval.

When a session needs you or finishes, the bell rings, a notification appears and its pane border lights up.

Splitting a big job into pieces and handing them out is on you.

The commander session splits the goal into tasks, starts workers and checks what they finish.

Two sessions edit the same file at the same time.

Sessions lock files; an edit to a file someone else has locked is blocked.

You find the conflict only after you merge.

The review screen shows conflicts, and other sessions touching the same files, before you merge.

Status markers

Every pane tells you what it is doing.

Legion doesn't guess from the screen. Claude Code sends Legion a hook event at every step, and the markers come from those events.

● running

A prompt was submitted and tools are running. The title shows the current tool.

◆ approval

An approval prompt is open. The bell rings; switch to the pane and answer.

✓ done

The turn is over. Claude's last message is saved on the task board.

○ idle

The session is ready for input. The next queued message goes out now.

✗ error

The turn ended with an API error. The task is marked "failed".

■ stopped

Stopped. Press r to pick the conversation up where it left off.

Workflow

From task to main branch in six steps.

  1. Write the task

    Press Ctrl+\ a in Legion, or run legion add "Add rate limiting to the API" from another terminal. Tasks added while Legion is closed wait on the board.

  2. Assign it

    Press Enter on the task in the board. Type a session name or leave it empty: Legion creates a new worktree and branch and starts Claude with the task as its first prompt.

  3. Watch

    Panes update on their own. Switch to the session that asks for approval and answer it; the others keep working.

  4. Review

    Ctrl+\ d shows the diff against the base branch, uncommitted files, a conflict check and other sessions touching the same files, all on one screen.

  5. Merge

    Press m on the review screen. If there are conflicts nothing changes and the files are listed. If your main checkout has uncommitted changes the merge is refused.

  6. Take a break

    Quit with Ctrl+\ q. Run legion again and the sessions that were running come back with their conversations, via --resume.

Commander

Give it the goal. It hands out the work.

The commander is a special Claude session that doesn't write code. It reads the codebase, splits the goal into tasks that touch as few of the same files as possible, and gives each task to a new worker session.

When a worker finishes a turn, Legion passes its last message to the commander automatically. The commander checks the work, asks for fixes if needed and tells you which branches to merge, in which order. Merging stays your call.

When you merge a branch, Legion tells the commander, and it closes that worker's pane. It never closes a session with uncommitted work and never deletes a branch that isn't merged.

Collaboration

Sessions see each other and talk.

Through Legion's tools, every session can list the others, send them messages and lock files. You don't have to set anything up.

If a session tries to edit a file another session has locked, Legion blocks it and tells Claude why. The output on the left is from a real run: beta was blocked, wrote to alpha, and the message reached alpha.

Keys

Prefix first, then the command.

Your keystrokes go to the focused Claude. For Legion commands, press and release the Ctrl+\ prefix, then the command key.

On keyboards where \ is awkward to reach (Turkish, German, French…), Ctrl4 works as the prefix too. To see what your terminal actually sends, run legion keytest.

To use ⌘⇧L in iTerm2: Settings → Profiles → Keys → Key Mappings → + → "Send Hex Code" 0x1c. Cmd shortcuts never reach terminal apps directly, so the mapping is needed.

Other agents

Other CLIs next to Claude Code.

Agents such as Codex, Gemini CLI, aider or cursor-agent are added under [agents] and run in the same grid, in their own worktrees. They have no Legion hooks, so their status is read from the screen: output after Enter means running, a quiet stretch means done, and a question like (y/n) near the cursor means it is waiting for approval.

[agents.codex]
command     = "codex"
resume_args = ["resume", "--last"]
prompt_arg  = true
idle_after  = "4s"
claudehooksMCPlocks Exact status, messaging and file locks.
codexscreen Status is inferred from output; no messaging or lock tools.
geminiscreen The same, with [agents.gemini].
cursor-agentscreen resume_args = ["--resume", "{id}"]
aiderscreen The first prompt is typed in (prompt_arg = false).

FAQ

Before you start.

Does it change my Claude Code settings?

No. Legion adds its hooks and tools only to the sessions it starts, with --settings and --mcp-config. Your files under ~/.claude stay as they are; Legion only reads the workspace-trust flag.

Does it cost anything?

Legion itself is free. Each session is an ordinary Claude Code session and uses your plan like any other. Four sessions use about four times as much in the same time.

Is my code sent anywhere?

Legion runs entirely on your machine. Sessions, tasks and the event log live in .legion/state.db in your project. The only thing that talks to the outside world is Claude Code itself.

What happens when I quit Legion?

Sessions stop; worktrees and branches stay. Run legion again and the sessions that were running come back with their conversations via --resume. A turn that was in progress is cut short.

How is my main branch protected?

Sessions never touch it; they work on their own branches. Merges happen only when you ask. On conflicts nothing changes, and if your main checkout has uncommitted changes the merge is refused.

Which terminals does it work in?

It has been used with iTerm2 and Terminal.app on macOS, and the test suite runs on macOS and Linux. On non-US keyboards use Ctrl4 as the prefix; legion keytest shows what your terminal sends.

How many sessions can I run at once?

The default limit is 8, set with max_sessions. In practice 2–4 sessions stay readable on screen and easy to merge.

Install

One line, then three commands.

macOS · LinuxIntel · Apple Silicon · ARMgit 2.38+Claude Code 2.1+
$ curl -fsSL https://bagsiz.github.io/legion-site/install.sh | sh   # ~/.local/bin/legion
$ cd ~/code/myapp
$ claude                   # once: "Yes, I trust this folder"
$ legion init              # sets up .legion/, hidden from git
$ legion                   # opens Legion; Ctrl+\ n starts a session
If something is off, legion doctor checks dependencies and trust. To update, run the same command again.
