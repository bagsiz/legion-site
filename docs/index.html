Legion documentation

Everything you need to run several Claude Code sessions side by side: how to install and update, what every key does, and how work gets from a session's branch into yours.

01Overview

Legion is a terminal app that runs several Claude Code sessions at once, each in its own pane. Every session works in its own git worktree on its own branch, so sessions never overwrite each other's files and your main checkout stays untouched until you merge.

  • Session: one Claude Code process in a pane. It lives in .legion/worktrees/<name> on the branch legion/<name>. Inside the pane you use Claude's own interface: you type, approve edits and run slash commands as usual.
  • Status: Legion knows whether each session is running, waiting for your approval, done or failed. The status comes from Claude Code hooks, not from guessing at the screen.
  • Task board: a shared list of work. Assigning a task sends its text to a session.
  • Review & merge: see a session's diff, check it against your branch for conflicts, then merge.
  • Commander: a special session that splits a large goal into tasks, starts workers and tells you what to merge.

02Install

Requirements: macOS or Linux (Intel or ARM), git 2.38 or newer, and Claude Code 2.1 or newer, logged in.

$ curl -fsSL https://bagsiz.github.io/legion-site/install.sh | sh

The script picks the build for your OS and CPU, downloads it from the releases page, checks its SHA-256 checksum and installs the legion binary to ~/.local/bin. Nothing else on your system is changed.

Two optional settings:

# a specific version
$ curl -fsSL https://bagsiz.github.io/legion-site/install.sh | LEGION_VERSION=v0.1.9 sh
# a different install directory
$ curl -fsSL https://bagsiz.github.io/legion-site/install.sh | LEGION_BIN_DIR=/usr/local/bin sh

If the script says the directory is not on your PATH, add it to your shell profile (for zsh: echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc) and open a new terminal.

Then check everything:

$ legion doctor

doctor checks git, Claude Code, your prefix key, notifications, whether a newer Legion is out, and, inside a project, whether Claude Code trusts the folder.

03Update

$ legion update            # install the latest release
$ legion update --check    # only tell me if there is one
$ legion update --version v0.1.8   # install a specific release (also to go back)

legion update downloads the release for your machine, verifies its checksum and replaces the binary you ran. If the checksum does not match, nothing is changed. A Legion window that is already open keeps running the old version until you quit and start it again; sessions pick up where they left off.

How you find out about new versions

When Legion starts, it checks GitHub in the background for a newer release, at most once a day. If there is one, the status bar shows v0.x.y available: legion update on the right, and legion doctor shows it too. The check sends nothing about you or your projects. To turn it off, set LEGION_NO_UPDATE_CHECK=1 in your shell profile.

Running the install command again also updates Legion; legion update is just quicker.

04Quick start

$ cd ~/code/myapp
$ claude        # once per project: answer "Yes, I trust this folder", then quit
$ legion        # sets the project up if needed and opens Legion

The first time you run legion in a folder it prepares it:

  • If the folder is not a git repository, it runs git init.
  • If the repository has no commits yet, it commits the files that are there (respecting .gitignore) as Initial commit, so sessions start from your code.
  • It creates .legion/ for its state and hides it from git via .git/info/exclude. Your .gitignore is not changed.

Legion never does this in your home directory or in /. legion init does the same setup without opening the interface.

Now press Ctrl+\ and then n, give the session a name and a first prompt, and it starts in its own pane. Start a second one the same way and the screen splits.

Why trust the folder first? Claude Code asks whether you trust a folder the first time it runs there. It remembers the answer for the main repository, and all of Legion's worktrees inherit it. If you skip this step, every new session asks again. legion doctor tells you if the folder is not trusted yet.

05The screen

Sessions are laid out in a grid: one fills the screen, two sit side by side, four make a 2×2 grid, and so on. Each pane has a title with its number, name, status and what it is doing right now (for example Bash: go test ./...), and the branch at the bottom. The focused pane has a pink border; your typing goes there.

Statuses

LabelMeaning
… startingClaude Code is launching.
○ idleReady and waiting for a prompt.
● runningWorking: thinking, reading files, running tools.
◆ approvalWaiting for you to approve something, such as an edit or a command. You get a bell and a desktop notification.
✓ doneFinished its turn. You get a bell and a notification.
✗ errorThe turn failed, for example because of an API error.
■ stoppedThe process is not running. Its worktree and conversation are kept; press r or Enter in the pane to resume.

Status bar

The bottom line shows the project name, how many sessions are in each status, and on the right either a short message about the last action, the list of prefix commands while the prefix is active, or a reminder of how to open help. The terminal window title shows (2) legion · myapp when two sessions need your attention.

Notifications

When a session needs approval or finishes, Legion rings the terminal bell and shows a desktop notification. In iTerm2, Ghostty, WezTerm and kitty the notification comes from the terminal itself, and clicking it brings the terminal to the front. In other terminals Legion uses terminal-notifier on macOS (brew install terminal-notifier) or notify-send on Linux; without them you get the bell only. legion doctor shows which one is used. Nothing is sent for the pane you are looking at while Legion is in the foreground. Both can be switched off under [notify].

06Keys

Every key you press goes to the focused session, exactly as if Claude Code were running on its own. Legion's own commands start with a prefix key, like tmux: press Ctrl+\, let go, then press the command key. While the prefix is active the status bar shows PREFIX and the list of commands.

Prefix, thenWhat happens
n or cNew session: asks for a name, an optional first prompt and, if you set up other agents, which agent to use.
← ↑ ↓ → or h j k lMove focus to the pane in that direction.
1 … 9Focus the session with that number.
Tab / Shift+TabNext / previous session.
zZoom: the focused pane fills the screen. Press again to go back to the grid.
tOpen the task board, or close it.
aAdd a task without opening the board.
dReview the focused session: diff, commit, merge.
bBroadcast a message to every session.
C (capital)Open the commander, or start one by giving it a goal.
sStop the focused session.
rResume the focused session if it is stopped.
xRemove the focused session (asks first).
qQuit Legion (asks first). Running sessions come back next time.
?Show help. Any key closes it.
the prefix againSend Ctrl+\ itself to the session.

In the dialogs Legion opens, Enter confirms a step, Esc cancels, and in yes/no questions the letters shown in the hint (y, n, …) choose.

If Ctrl+\ is awkward on your keyboard

On Turkish and many other non-US layouts the backslash is hard to reach. Ctrl+4 sends the same signal and works as the prefix out of the box. To use something else, run legion keytest, press the key you want and copy the name it prints into .legion/config.toml:

[keys]
prefix = "ctrl+\\, ctrl+g"   # several prefixes, comma-separated

Cmd shortcuts never reach terminal programs. In iTerm2 you can still map one: Settings → Profiles → Keys → Key Mappings → + → choose Cmd+Shift+L → action “Send Hex Code” → 0x1c.

07Sessions

Start one

Press the prefix and n. Give it a name of lowercase letters, digits and dashes (or leave it empty for an automatic one) and, optionally, a first prompt; Claude starts working on it right away. From another terminal: legion session new docs -p "Tidy up the docs folder".

Each session gets a fresh worktree branched from your base branch (the branch you were on when you ran legion init, usually main). It sees committed code only: uncommitted changes in your main checkout are not in its worktree.

Stop, resume, remove

  • Stop (s or legion stop name) ends the Claude process. The worktree, branch and conversation stay.
  • Resume (r, or Enter in a stopped pane, or legion resume name) starts it again with --resume, so the conversation continues where it stopped.
  • Remove (x) deletes the worktree. The branch is kept, so no committed work is lost. If the worktree has uncommitted changes Legion refuses, unless you choose f to discard them.

Quitting

Quitting (prefix q) stops all sessions but remembers which were running. Next time you run legion in the project, those sessions resume automatically with their conversations. Sessions you stopped yourself stay stopped. A turn that was in progress when you quit is cut short.

08Task board

The board is a shared to-do list for the project. Prefix t opens it on the right side of the screen; on a narrow terminal it takes the whole screen.

On the boardWhat happens
↑ ↓ / k jSelect a task.
aAdd a task: a title and an optional description.
EnterAssign the selected task to a session by name, or to new to start a session for it. The task text is sent to that session as a prompt.
gGo to the session the task is assigned to.
dMark the task done.
rReopen it.
xDelete it (asks first).
TabLeave the board open but give the keyboard back to the panes.
Esc / qClose the board.

Task statuses follow the session: todo → assigned → in_progress while it works → review when it finishes → merged when you merge its branch, or failed.

If the session you assign to is busy, the prompt is queued and delivered as soon as it is idle. From the command line: legion add "Fix the signup form" --to web, legion assign 3 api, legion ls.

09Review & merge

Prefix d opens a review of the focused session. At the top it shows what would happen if you merged:

  • how many commits the branch is ahead, and which files changed;
  • uncommitted files in the session's worktree;
  • whether merging into your base branch would conflict, checked with git merge-tree without touching any files;
  • other sessions that changed the same files, so you can merge in a sensible order.

Below that is the full diff, including new untracked files.

In the reviewWhat happens
↑ ↓ j k, Space / b, g / GScroll by line, by page, to the top / bottom.
cCommit the session's uncommitted changes. An empty message uses the task title.
mMerge. Then y merges, r merges and removes the session (worktree and branch), n cancels. Uncommitted changes are committed first.
rRefresh.
Esc / qClose.

How the merge is done

  • If there are conflicts, Legion does not merge. Ask the session to rebase or resolve them, then review again.
  • If your base branch is checked out in your main folder, Legion runs git merge --no-ff there. If that folder has uncommitted changes, the merge is refused so your work is never mixed in.
  • If the base branch is not checked out, Legion creates the merge commit directly on the branch without touching any working folder.
  • With “merge and remove”, the session is stopped first, and the branch is deleted only if it is fully merged.

Same from the command line: legion diff api --stat, legion merge api --commit --rm.

10Broadcast & messages

Prefix b sends one message to every session, for example “rebase on main and run the tests”. Sessions that are idle or done get it at once. Sessions that are busy get it when they finish their current turn, so nothing interrupts work in progress.

$ legion broadcast "Rebase on main and run the tests"
$ legion send api "Also add a test for the 429 response"   # one session

11Commander

The commander is a Claude session that manages the others instead of writing code. Give it a goal and it plans the work, starts workers and keeps track of them.

$ legion commander "Add user accounts: signup, login, password reset, with tests"

Or press prefix C in Legion and type the goal. Pressing prefix C again later takes you back to the commander.

What it does:

  1. Reads the code and splits the goal into tasks that can be done in parallel without stepping on each other.
  2. Puts them on the task board and starts a worker session for each.
  3. Is told automatically when a worker finishes, with the worker's last message. It reviews the diff and sends follow-ups if something is missing.
  4. Tells you which branches are ready and in what order to merge them. It never merges itself; merging stays your decision.
  5. Is told when you merge a worker, and closes finished workers' panes. A worker with uncommitted changes is never closed, and its branch is deleted only if fully merged.

There is one commander per project. Its tools: create_task, assign_task, create_session, broadcast, session_status, get_diff, close_session.

12Messaging & file locks

Every Claude session started by Legion gets a few extra tools, so sessions can coordinate without you relaying messages:

ToolWhat it does
list_sessionsWho else is working, on which branch, on what.
send_messageSend a message to another session or to all of them.
lock_files / unlock_filesClaim files before changing them. All or nothing: if any file is held by someone else, nothing is locked and the owner is named.
list_locksAll current locks.
list_tasksThe task board.

Locks are enforced: if a session tries to edit a file another session has locked, the edit is blocked and Claude is told who holds it. This covers Claude's edit tools (Edit, Write, MultiEdit, NotebookEdit); writes made through shell commands cannot be blocked. Locks are released when a session is merged or removed. See them with legion locks.

These tools are allowed without a permission prompt, and they only reach your local Legion.

13Other agents

Legion is built for Claude Code, but it can also run other agent CLIs such as Codex, Gemini CLI, aider or cursor-agent in a pane. Add them to the config:

[agents.codex]
command = "codex"
resume_args = ["resume", "--last"]
prompt_arg = true      # pass the first prompt as an argument (otherwise it is typed in)
idle_after = "4s"      # this long without output after a prompt counts as done

Pick the agent in the last step of the new-session dialog, or with legion session new name --agent codex. default_agent changes the default.

These agents have no hooks, so their status is inferred from the screen: output after you press Enter means running, silence for idle_after means done, and a question like (y/n) on the last lines means approval. They do not get the messaging and locking tools.

14Command line

Everything below also works from another terminal while Legion is open; the interface updates immediately. add, ls, diff, merge and task also work when Legion is closed.

legion add "title" [-b text] [--to name | --new]Add a task; optionally assign it to a session or to a new one.
legion assign 3 apiAssign task #3 to api (or new).
legion lsShow the board and the sessions.
legion task done|fail|reopen|rm 3Change or delete task #3.

legion diff api [--stat]Show a session's changes and the conflict check.
legion merge api [--commit] [--rm]Merge a session; --commit commits its uncommitted changes first, --rm removes it afterwards.

legion update [--check] [--version v]Update Legion (details).

legion keytestShow the name of each key you press, for choosing a prefix.
legion --versionShow the installed version.

legion hook and legion mcp also exist; Claude Code calls them, you don't need to.

15Configuration

Legion reads ~/.config/legion/config.toml for all projects and .legion/config.toml for one project; project settings win. legion init writes a commented project file. All keys are optional:

base_branch = "main"        # sessions branch off and merge into this
branch_prefix = "legion/"   # session branches are legion/<name>
max_sessions = 8            # at most this many running at once
# default_agent = "claude"

[keys]
prefix = "ctrl+\\, ctrl+4"  # comma-separate several; see legion keytest

[claude]
command = "claude"
# permission_mode = "acceptEdits"   # default | acceptEdits | plan | auto | bypassPermissions
# extra_args = ["--model", "opus"]

[notify]
bell = true
desktop = true

Legion never changes your Claude Code settings. It gives each session its hooks and tools on the command line (--settings, --mcp-config), and only reads Claude's config to see whether a folder is trusted.

Environment variables

LEGION_NO_UPDATE_CHECK=1Turn off the daily update check.
LEGION_HOMEWhere Legion keeps machine-wide data (default ~/.legion).
LEGION_VERSION, LEGION_BIN_DIRFor the install script: which version, and where to install.

16Where things live

~/.local/bin/legionThe program.
<project>/.legion/config.tomlProject settings.
<project>/.legion/state.dbSessions, tasks, locks and the event log (SQLite).
<project>/.legion/worktrees/<name>Each session's working folder.
<project>/.legion/logs/Logs.
~/.legion/projects.jsonThe list behind legion projects.
~/.legion/run/Sockets that let the CLI and hooks talk to a running Legion.
~/.legion/update-check.jsonWhen the update check last ran and what it found.

.legion/ is listed in .git/info/exclude, so git and most tools ignore it. Nothing leaves your machine except what Claude Code itself sends, and the daily version check.

17Troubleshooting

Start with legion doctor; it catches most problems and says how to fix them.

Every new session asks whether I trust the folder.
Run claude once in the project's main folder and answer “Yes, I trust this folder”. Worktrees inherit that answer.
The prefix key does nothing.
Run legion keytest and press Ctrl+\. If nothing or something else shows up, your terminal or keyboard layout does not send it. Try Ctrl+4, or put the key keytest shows into [keys] prefix.
“is Legion already running for this project?”
Legion is open for this project in another terminal window. Use that one, or quit it first.
“branch has no commits yet”
Sessions branch off a commit. Run legion init (it makes the first commit) or commit something yourself.
The merge is refused because of uncommitted changes.
Your main folder has uncommitted work on the base branch. Commit or stash it, then merge again. Legion refuses so your work is never mixed into a merge.
A session shows the wrong status.
Statuses come from Claude Code hooks. If you updated Claude Code and they look off, legion doctor shows the Claude version Legion was tested with. Press Esc in the pane to interrupt a stuck turn.
legion update fails with “permission denied”.
The folder the binary is in is not writable for you, for example if you installed to /usr/local/bin. Run the install command again with the same LEGION_BIN_DIR and sudo if needed.
A session needs something from my main folder that isn't committed.
Sessions only see committed code. Commit it on your base branch; new sessions will have it, and existing ones can merge or rebase onto it.

18Uninstall

$ rm ~/.local/bin/legion
$ rm -rf ~/.legion
# in each project, after merging or saving any work you want to keep:
$ rm -rf .legion && git worktree prune
$ git branch --list 'legion/*'        # session branches; delete the ones you don't need
